<!-- extension-point: section:Server-side security rules -->

### 7.7 Auth strategy (capability `auth-provider`)

Ativada quando algum card que provê `auth-provider` está ativo. Em v1 os
providers são mutuamente exclusivos (label singular): `firebase-auth` OU
`auth-jwt-bearer`. Card contribui:

- Fluxo de sign-in / sign-out / session refresh
- Como o token é propagado para network calls (interceptor Ktor para
  Bearer tokens; sessão gerenciada pelo SDK no caso Firebase)
- Storage de credentials/tokens (secure storage / sessão em memória)
- Mapeamento de erros de auth para `NetworkError`/`AuthError` em
  `shared:core/error/`

Cards que provêem `auth-token-bearer` (Firebase e JWT ambos) contribuem
o interceptor Bearer para `http-client`. Quando há `firebase-auth`,
adicionalmente é provido `auth-firebase-managed` (sessão sem necessidade
de manipular tokens manualmente para chamadas Firebase SDK).

_Sem card `auth-provider` ativo:_ subseção fica vazia — feature opera
anonimamente ou herda sessão de outro feature.
